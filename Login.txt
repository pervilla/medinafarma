📋 ANÁLISIS COMPLETO DEL SISTEMA DE LOGIN
CONTEXTO GENERAL
Este es un sistema de autenticación empresarial antiguo (VB6) con características peculiares:

Control de fecha de proceso empresarial (no usa la fecha actual del sistema necesariamente)
Validación contra un calendario corporativo
Sistema de "recordar usuario"
Bloqueo por fecha específica (posiblemente piratería/licenciamiento)
Multi-nivel de usuarios con diferentes privilegios

**¿Por qué esta validación?**

- Es una advertencia para evitar errores de registro

│ Usa la clave │      │ Busca en BD la   │

│ el usuario   │      │ "SUPERVISOR"     │

       │                       │

               ▼
┌─────────────────────────────────────┐
│ PUB_CLAVE = clave a usar            │
└─────────────────────────────────────┘
Lógica de seguridad interesante:
vbIf LK_CODUSU = "ADMIN" Or LK_CODUSU = "SUPERVISOR" Or LK_CODUSU = "SUPER" Then
   PUB_CLAVE = Trim(Text1.Text)  ' Usa lo que escribió
Else
   ' Para usuarios normales, usa la clave del SUPERVISOR
   Do Until usu.EOF
      If Trim(usu!usu_key) = "SUPERVISOR" Then
        PUB_CLAVE = Trim(usu!USU_CLAVE)
        Exit Do
      End If
      usu.MoveNext
   Loop
End If
```

**Esto significa:**
- Usuarios normales NO tienen clave propia para login
- Todos comparten la clave del usuario "SUPERVISOR"
- Solo admin/super/supervisor pueden tener claves únicas

## 🎯 CARACTERÍSTICAS CLAVE DEL SISTEMA

### **1. Sistema de "Recordar Usuario"**
```
Archivo: C:\CODUSU$.txt
Contenido: [USUARIO][CHECKBOX]
Ejemplos:
  - "ADMIN0" = Usuario ADMIN, NO recordar contraseña
  - "JUAN1"  = Usuario JUAN, SÍ recordar (auto-login)
2. Jerarquía de Usuarios
NivelUsuarioPrivilegios🔴 MáximoSUPERPuede saltarse calendario bloqueado🟠 AltoADMINLogin propio, tiene clave de gerencia🟡 MedioSUPERVISORLogin propio, su clave es usada por usuarios normales🟢 NormalOtrosUsan clave del SUPERVISOR
3. Calendario Corporativo
sql-- Tabla: cal_llave
SELECT * FROM cal_llave 
WHERE CAL_FECHA = '2026-02-04'
  AND CAL_INDICE = 1  -- 1 = Activo, 0 = Bloqueado
```

**Casos de uso:**
- Cerrar períodos contables (fin de mes no permite más registros)
- Días festivos o no laborables
- Períodos de auditoría

### **4. Dos Claves por Usuario**
```
usu_clave  = Clave de login
usu_clave2 = Clave de gerencia (solo ADMIN)
La "clave de gerencia" probablemente se usa para:

Autorizar operaciones críticas
Anular transacciones
Acceder a reportes confidenciales


🔒 ANÁLISIS DE SEGURIDAD
Vulnerabilidades Detectadas:

❌ Archivo de texto plano

vb   Open "C:\CODUSU$.txt" For Output
   Print #1, wWRITE  ' Guarda en texto plano!

Usuario y checkbox sin encriptar
Cualquiera puede editar el archivo


❌ Clave hardcodeada

vb   If InputBox(...) = "159357852456" Then

Clave de desbloqueo visible en código
No hay ofuscación


❌ Usuarios sin clave propia

vb   ' Usuarios normales usan la clave del SUPERVISOR

Si un usuario normal es comprometido, todos lo son
No hay trazabilidad individual


❌ Sin validación de contraseña

El código NO valida la contraseña ingresada contra la BD
Solo obtiene la clave pero no la compara
Parece que falta código o se valida en otro lugar




📝 RESUMEN EJECUTIVO
¿Qué hace este sistema?
Es un sistema de autenticación empresarial que:

Controla el acceso por usuario
Valida que se trabaje en fechas permitidas por el calendario corporativo
Permite "recordar usuario" para siguiente sesión
Implementa jerarquía de usuarios con privilegios
Tiene protección anti-piratería por fecha

Flujo en una frase:

Valida usuario → Verifica fecha en calendario → Compara con fecha PC → Obtiene clave según nivel → Guarda preferencias → Entra al sistema

Para implementar en PHP necesitas:

Tabla cal_llave (calendario)
Tabla usu (usuarios con usu_clave y usu_clave2)
Tabla gen (configuración con gen_bloqueo)
Sistema de sesiones PHP
Archivo/BD para guardar "recordar usuario"
